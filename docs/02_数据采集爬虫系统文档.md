# 数据采集系统概述

Kronos系统的数据采集模块负责从多个金融数据源获取实时和历史数据,包括:
- 股票基础数据(K线、成交量等)
- 板块情绪数据
- 投资者情绪数据
- 龙虎榜数据
- 新闻公告数据

采集系统具备以下特性:
- **多源爬虫**: 支持Tushare、东方财富、同花顺、雪球等多个数据源
- **智能降级**: 主数据源失败时自动切换备选源
- **反爬虫机制**: User-Agent轮换、请求延迟、Playwright浏览器渲染
- **数据验证**: 自动检测数据质量和完整性
- **缓存优化**: 减少重复请求,提升性能

# 反爬虫优化总结

## 问题诊断

### 原始问题
使用投资机会挖掘功能后，所有爬虫数据源都返回 `ERR_EMPTY_RESPONSE` 错误，导致无法获取任何股票数据。

### 根本原因分析
1. **请求频率过高**: 原配置为10次/分钟，对于金融数据网站来说过于频繁
2. **重试延迟不足**: 基础延迟只有2秒，遇到反爬虫拦截后重试过快
3. **缺乏智能冷却**: 连续失败后没有自适应的冷却机制
4. **ERR_EMPTY_RESPONSE处理不当**: 这是最严重的反爬虫信号，但没有特殊处理
5. **批量请求策略不合理**: 尝试获取365天的5分钟数据(17520个数据点)，分批请求过于密集

## 优化方案

### 1. 创建通用反爬虫增强模块 (`anti_crawler_helper.py`)

#### RateLimiter（智能频率限制器）
- **自适应频率控制**: 动态调整请求间隔
- **突发控制**: 限制短时间内的连续请求
- **冷却机制**:
  - 连续3次错误触发冷却
  - 冷却时间指数增长，最多5分钟
  - ERR_EMPTY_RESPONSE触发30-60秒强制冷却

#### SmartRetryStrategy（智能重试策略）
- **指数退避**: 重试延迟 = 基础延迟 × 2^尝试次数
- **随机抖动**: ±30%的随机变化，避免所有请求同步
- **错误类型感知**:
  - ERR_EMPTY_RESPONSE: 延迟×2
  - TIMEOUT: 延迟×1.5
  - 其他错误: 标准延迟

#### RequestOptimizer（请求优化器）
- 整合频率限制和智能重试
- 统计请求成功率
- 自动错误分类和上报

### 3. 核心优化逻辑

#### 请求执行流程
```
1. 频率限制检查
   ├─ 检查是否在冷却期
   ├─ 检查1分钟内请求数
   ├─ 检查最小请求间隔
   └─ 通过后进入步骤2

2. 执行请求(带重试)
   ├─ 添加随机延迟(模拟人类)
   ├─ 发送HTTP请求
   ├─ 失败时错误分类
   ├─ 根据错误类型计算退避时间
   └─ 重试或报告失败

3. 结果处理
   ├─ 成功: 重置错误计数
   ├─ 失败: 增加错误计数
   └─ ERR_EMPTY_RESPONSE: 触发强制冷却
```

#### 错误分类系统

## 技术细节

### 冷却算法
```python
# 连续错误触发冷却
if consecutive_errors >= 3:
    cooldown = min(60 * (2 ** (errors - 3)), 300)
    # 错误次数: 3  → 冷却60秒
    # 错误次数: 4  → 冷却120秒
    # 错误次数: 5  → 冷却240秒
    # 错误次数: 6+ → 冷却300秒(最多5分钟)

# ERR_EMPTY_RESPONSE特殊处理
if error_type == "ERR_EMPTY_RESPONSE":
    cooldown = 30 + random.uniform(10, 30)  # 30-60秒
```

### 指数退避算法
```python
def get_retry_delay(attempt, error_type):
    # 基础延迟: 3秒, 尝试次数: 0, 1, 2
    exponential = 3.0 * (2 ** attempt)
    # 尝试0: 3秒, 尝试1: 6秒, 尝试2: 12秒

    jitter = exponential * random.uniform(-0.3, 0.3)
    # ±30%随机抖动

    delay = exponential + jitter

    if error_type == "ERR_EMPTY_RESPONSE":
        delay *= 2  # 反爬虫错误延迟加倍

    return min(delay, 60.0)  # 最多60秒
```

# 板块名称采集修复总结

## 问题描述

在批量股票分析过程中，板块名称显示为默认值"行业板块"而非实际的板块名称（如"新能源汽车"、"半导体"等）。

## 问题根源

1. **主API不稳定**: `http://push2.eastmoney.com/api/qt/stock/get` 频繁返回502 Bad Gateway错误
2. **缺少备用数据源**: 主API失败后没有备用方案获取板块信息
3. **sector_code缺失**: 主API失败时连sector_code都无法获取，导致后续查询逻辑无法触发

## 修复方案

### 1. 添加备用API获取板块代码和名称

```python
def _request_with_retry(self, url, params, max_retries=3):
    """带重试的请求"""
    for i in range(max_retries):
        try:
            response = requests.get(url, params=params, timeout=10)
            if response.status_code == 200:
                return response
            time.sleep(1 * (i + 1))  # 指数退避
        except Exception:
            if i == max_retries - 1:
                raise
    return None
```

# 板块情绪API 502错误问题分析与解决

## 问题现象

```
⚠️  获取板块信息失败: Expecting value: line 1 column 1 (char 0)
⚠️  获取板块情绪失败: Expecting value: line 1 column 1 (char 0)
🔍 sector_info: sector_name=未知, success=False
🔍 sector_sentiment: overall=数据不足, change_pct=0, data_source=default
```

## 问题根源

### 1. HTTP 502 Bad Gateway
通过测试发现,东方财富API返回了HTTP 502错误:

```bash
请求URL: http://push2.eastmoney.com/api/qt/stock/get
HTTP状态码: 502
响应内容长度: 0
JSON解析失败: Expecting value: line 1 column 1 (char 0)
```

### 2. 原因分析

**HTTP 502错误**表示:
- **网关错误**: 服务器作为网关或代理,从上游服务器收到无效响应
- **服务不可用**: API服务临时过载或维护
- **限流/反爬**: 请求频率过高被限流
- **网络问题**: 网络连接不稳定

**为什么响应体为空?**
- 502错误通常不返回响应体
- 导致 `response.text` 为空字符串
- JSON解析时出现 `Expecting value: line 1 column 1 (char 0)` 错误

### 3. 为什么其他功能正常?

| 功能 | 状态 | 原因 |
|------|------|------|
| Playwright获取新闻 | ✅ 成功 | 使用浏览器爬取,不依赖此API |
| 股吧情绪 | ✅ 成功 | 使用不同的API端点 `guba.eastmoney.com` |
| 板块情绪 | ❌ 失败 | 依赖 `push2.eastmoney.com` API |

## 解决方案

### 方案1: 增强重试机制 ✅ 已实施

修改 `analysis/sector_api.py`,添加智能重试:

```python
# 重试机制: 最多3次
max_retries = 3
data = None
last_error = None

for attempt in range(max_retries):
    try:
        response = requests.get(url, params=params, headers=headers, timeout=10)

        # 检查HTTP状态码
        if response.status_code == 502:
            if attempt < max_retries - 1:
                time.sleep(1)  # 等待1秒后重试
                continue
            else:
                raise Exception("HTTP 502")

        if response.status_code != 200:
            if attempt < max_retries - 1:
                time.sleep(1)
                continue
            else:
                raise Exception(f"HTTP {response.status_code}")

        # 检查响应内容
        if not response.text or response.text.strip() == '':
            if attempt < max_retries - 1:
                time.sleep(1)
                continue
            else:
                raise Exception("空响应")

        # 解析JSON
        data = response.json()
        break  # 成功,跳出重试循环

    except requests.exceptions.Timeout:
        if attempt < max_retries - 1:
            time.sleep(2)
            continue
    except requests.exceptions.RequestException as e:
        if attempt < max_retries - 1:
            time.sleep(2)
            continue

if data is None:
    raise Exception(f"API请求失败(已重试{max_retries}次): {last_error}")
```

**优化效果**:
- ✅ 自动重试3次
- ✅ 每次重试间隔1-2秒
- ✅ 明确区分502、超时、空响应等错误
- ✅ 提供详细的错误信息

# 情绪数据缓存优化总结

## 问题背景

在投资机会挖掘报告生成过程中,发现情绪面筛选数据都是假数据或N/A,分析发现主要问题:

1. **重复数据获取**: 批量分析100只股票时,每只股票都重复调用相同的大盘/板块情绪API
   - 大盘数据(上证/深证/创业板/科创板)被重复获取100次
   - 同一板块的数据被该板块内所有股票重复获取

2. **API频繁失败**: 大量重复请求导致:
   - 触发东方财富API限流
   - 网络错误频繁发生
   - 后续请求返回空数据或默认值

3. **缓存机制不足**:
   - 原有缓存是股票级别,无法跨股票共享
   - 缓存时间短(600秒)
   - 无全局缓存管理

## 解决方案

### 1. 创建全局缓存管理器 (`analysis/sentiment_cache_manager.py`)

**核心特性**:
- **单例模式**: 确保全局唯一实例
- **内存+文件双层缓存**:
  - 内存缓存: 快速访问
  - 文件缓存: 持久化,进程重启可用
- **智能缓存时间**:
  - 大盘情绪: 10分钟
  - 板块情绪: 10分钟
  - 资金流向: 5分钟
  - 龙虎榜: 30分钟

**API设计**:
```python
# 获取全局缓存实例
cache = get_sentiment_cache()

cache.get_overall_market()
cache.set_overall_market(data)

# 板块情绪(按板块名称共享)
cache.get_sector('半导体')
cache.set_sector('半导体', data)

# 资金流向(按股票代码)
cache.get_capital_flow('688343')
cache.set_capital_flow('688343', data)

# 龙虎榜(按股票代码)
cache.get_dragon_tiger('688343')
cache.set_dragon_tiger('688343', data)

# 管理功能
```

```python
    sector_info = get_stock_sector_info(self.stock_code)
    sector_name = sector_info.get('sector_name')

    # 1. 尝试从全局缓存获取板块情绪(按板块名称)
    cached_sentiment = self.global_cache.get_sector(sector_name)
    if cached_sentiment:
        return cached_sentiment

    # 2. API获取
    sector_sentiment = get_sector_sentiment(self.stock_code)

    # 3. 保存到全局缓存
    self.global_cache.set_sector(sector_name, sector_sentiment)

    return sector_sentiment
```

# 数据采集JSON解析失败修复总结

## 问题描述

在批量股票分析过程中，出现以下三类数据采集失败：

1. **板块情绪数据采集失败**: `⚠️ 获取板块情绪失败: Expecting value: line 1 column 1 (char 0)`
2. **财务指标数据采集失败**: `⚠️ 获取财务指标失败: Expecting value: line 1 column 1 (char 0)`
3. **行业对比数据采集失败**: `⚠️ 获取行业对比数据失败: Expecting value: line 1 column 1 (char 0)`

## 问题根源

错误信息 `Expecting value: line 1 column 1 (char 0)` 是Python的 `json.JSONDecodeError` 异常，表明在解析JSON时遇到了空字符串或无效内容。

经过分析，问题的根源是：
- API请求返回了HTTP错误状态码（如502 Bad Gateway）
- API返回了空响应
- API被反爬虫机制限流或拦截
- 代码直接调用 `response.json()` 而没有事先检查响应状态

## 修复方案

### 1. 添加安全的JSON解析方法

在两个关键文件中添加了 `_safe_json_parse()` 辅助方法：

**文件**: `analysis/investor_sentiment.py` 和 `analysis/fundamental_data_collector.py`

```python
def _safe_json_parse(self, response, api_name: str = "API"):
    """
    安全解析JSON响应，添加详细日志和错误处理

    Args:
        response: requests.Response对象
        api_name: API名称，用于日志记录

    Returns:
        解析后的JSON对象，失败时返回None
    """
    try:
        # 检查HTTP状态码
        if response.status_code != 200:
            print(f"   ⚠️  {api_name} HTTP错误: {response.status_code}")
            print(f"   调试: URL={response.url}")
            return None

        # 获取响应文本
        text = response.text.strip()

        # 检查是否为空
        if not text:
            print(f"   ⚠️  {api_name} 返回空响应")
            print(f"   调试: URL={response.url}")
            return None

        # 尝试解析JSON
        try:
            data = response.json()
            return data
        except json.JSONDecodeError as je:
            print(f"   ⚠️  {api_name} JSON解析失败: {str(je)}")
            print(f"   调试: URL={response.url}")
            print(f"   调试: 响应内容前200字符: {text[:200]}")
            return None

    except Exception as e:
        print(f"   ⚠️  {api_name} 解析异常: {str(e)}")
        return None
```

### 2. 替换所有不安全的JSON解析调用

将所有 `data = response.json()` 替换为 `data = self._safe_json_parse(response, "API名称")`

#### analysis/investor_sentiment.py 修复的方法:

## 技术要点

### 1. 防御性编程
- 在调用外部API时，始终假设可能失败
- 使用多层检查：HTTP状态码 → 响应内容 → JSON解析 → 数据有效性

### 2. 降级策略
- 主API失败 → 备用API
- 所有API失败 → 缓存数据
- 无缓存 → 默认值

### 3. 日志最佳实践
- 记录失败的API名称和URL
- 输出响应片段以便调试
- 使用表情符号增强可读性 (⚠️/✅)
