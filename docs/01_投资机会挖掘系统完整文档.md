### 关键特性

#### 1. 批量分组处理

**问题**：一次性提交100个并发任务，可能导致：
- 内存占用过高
- 网络请求拥堵
- 系统资源耗尽

**解决方案**：分批处理
```python
# 将100只股票分成5批，每批20只
batches = [stocks[i:i+20] for i in range(0, 100, 20)]

for batch in batches:
    # 批内并发处理
    with ThreadPoolExecutor(max_workers=10) as executor:
        futures = [executor.submit(analyze_stock, s) for s in batch]
        for future in as_completed(futures):
            result = future.result()
```

**优势**：
- 内存占用可控
- 网络请求平滑
- 可根据系统性能动态调整批次大小

#### 2. 并发线程池

**技术选型**：`ThreadPoolExecutor`（I/O密集型任务最优）

**配置参数**：
```python

# 根据系统性能调整：
# - CPU核心数较少: --workers 5
# - CPU核心数较多: --workers 20
# - 网络带宽限制: --workers 5-8
# - 高性能服务器: --workers 15-20
```

#### 3. 超时控制机制

**问题**：单只股票分析卡死会导致整个批次阻塞

**解决方案**：双重超时控制

**外层超时**（线程级）：
```python
def _analyze_single_stock_with_timeout(stock: Dict) -> Dict:
    """带超时的股票分析"""
    result = [None]

    def worker():
        result[0] = analyze_stock(stock)

    thread = threading.Thread(target=worker)
    thread.daemon = True
    thread.start()
    thread.join(timeout=10)  # 10秒超时

    if thread.is_alive():
        logger.warning(f"股票 {stock['code']} 分析超时")
        return None
    return result[0]
```

#### 智能容差机制

**传统一票否决问题**：
- 某一维度稍差就被淘汰
- 优秀股票可能因单一维度错过

**智能容差方案**（默认启用）：
- **降权而非淘汰**：未通过阶段的股票不直接淘汰，而是降低评分
- **容差惩罚**：根据未通过阶段数量计算惩罚系数
- **综合评估**：基于调整后得分最终判断

**惩罚计算**：
```python
容差惩罚 = 未通过阶段数 * 0.15  # 每阶段惩罚15%
调整后得分 = 原始得分 * (1 - 容差惩罚)

# 示例：
# 原始得分: 75分
# 未通过1个阶段: 75 * (1 - 0.15) = 63.75分
# 未通过2个阶段: 75 * (1 - 0.30) = 52.5分（不通过）
```

**开关控制**：
```bash
# 启用智能容差（默认）
python scripts/run_opportunity_discovery.py

# 禁用智能容差，使用传统一票否决
python scripts/run_opportunity_discovery.py --no-smart-tolerance
```

### 6. 价格连续性修正

```
历史最后价格: 100.0元
预测第一价格:  95.0元
跳空幅度: -5% (超过3%阈值)
```

#### 解决方案

```python
def fix_price_continuity(historical_df, predicted_df):
    """自动修正价格断层"""
    last_price = historical_df['close'].iloc[-1]
    first_pred = predicted_df['close'].iloc[0]
    gap = abs(first_pred - last_price) / last_price

    if gap > 0.03:  # 缺口>3%
        # 平滑过渡修正
        scale_factor = last_price / first_pred
        predicted_df[['open', 'high', 'low', 'close']] *= scale_factor
```

#### 2.1 `_fetch_historical_data()` 方法重构

**新增功能**：
1. **缓存数据质量验证**：
   - 从缓存获取数据后进行质量检查
   - 验证必需字段和最小行数

2. **数据质量二次验证**：

**代码示例**（Lines 202-253）：
```python
def _fetch_historical_data(self, stock_code: str) -> Optional[pd.DataFrame]:
    cache_key = f"historical_data:{stock_code}:daily:365d"

    # 尝试从缓存获取
    if self.use_cache and self.cache:
        cached_data = self.cache.get(cache_key)
        if cached_data is not None:
            # 验证缓存数据质量
            is_valid, error_msg = validate_data_quality(
                cached_data,
                required_fields=['timestamps', 'open', 'high', 'low', 'close', 'volume'],
                min_rows=30,
                data_type="缓存的历史数据"
            )
            if is_valid:
                return cached_data
            else:
                logger.warning(f"缓存数据质量不合格: {error_msg}，重新获取")
                self.cache.delete(cache_key)

    try:
        # 使用重试机制获取数据
        df = self._fetch_historical_data_with_retry(stock_code)

        # 数据质量验证
        is_valid, error_msg = validate_data_quality(
            df,
            required_fields=['timestamps', 'open', 'high', 'low', 'close', 'volume'],
            min_rows=30,
            data_type="历史K线数据"
        )

        if not is_valid:
            logger.warning(f"{stock_code}: {error_msg}")
            return None

        # 保存到缓存
        if self.use_cache and self.cache:
            self.cache.set(cache_key, df, ttl=600)

        return df
    except Exception as e:
        logger.error(f"获取历史数据失败: {e}")
        return None
```

#### 2.2 `_fetch_historical_data_with_retry()` 新增方法

**功能**：带重试机制的历史数据获取核心逻辑

**代码示例**（Lines 255-320）：
```python
@exponential_backoff_with_jitter(
    max_retries=3,
    base_delay=1.0,
    max_delay=10.0,
    exceptions=(Exception,)
)
def _fetch_historical_data_with_retry(self, stock_code: str) -> Optional[pd.DataFrame]:
    """带重试机制的历史数据获取"""
    from scripts.fetch_data import MultiSourceDataFetcher
    import asyncio

    fetcher = MultiSourceDataFetcher()

    async def _run():
        df = await fetcher.fetch_stock_data(
            symbol=stock_code,
            start_date=start_date,
            end_date=end_date,
            freq='daily',
            source='auto',
            auto_extend=True,
            min_days=240
        )
        await fetcher.close()
        return df

    # 运行异步获取
    df = asyncio.run(_run())

    # 基本校验 - 失败时抛出异常以触发重试
    if df is None or df.empty:
        raise ValueError(f"{stock_code}: 数据获取返回空结果")

    # 确保列名兼容
    required_cols = {'timestamps', 'open', 'high', 'low', 'close', 'volume'}
    if not required_cols.issubset(set(df.columns)):
        raise ValueError(f"{stock_code}: 数据列不完整")

    # 数据清洗
    df = df[list(required_cols)].copy()
    df['timestamps'] = pd.to_datetime(df['timestamps'])
    df = df.sort_values('timestamps').reset_index(drop=True)

    return df
```

**重试策略**：
- **第1次失败**: 等待1秒后重试
- **第2次失败**: 等待2秒后重试
- **第3次失败**: 等待4秒后重试
- **3次全部失败**: 抛出异常，外层捕获并返回None

**异常处理**：
- 数据为空 → 抛出 `ValueError` 触发重试
- 列不完整 → 抛出 `ValueError` 触发重试
- 网络异常 → 被装饰器捕获并重试
- 重试耗尽 → 外层 try-except 捕获，记录日志并返回 None

### 2. ✅ 智能容差机制

**核心理念**: 不满足条件时降权而非直接淘汰，允许综合实力强的股票通过筛选。

#### **传统模式 vs 智能容差**

| 模式 | 筛选逻辑 | 通过条件 | 优势 | 劣势 |
|-----|---------|---------|------|------|
| **传统一票否决** | 任一阶段不通过即淘汰 | 全部阶段通过 | 质量保证强 | 可能错失好股票 |
| **智能容差** | 不通过时降权，计算调整分数 | 调整后分数≥50 | 综合评价，更全面 | 需要更复杂的判断 |

#### **惩罚权重规则**

```python
# 每个未通过的阶段增加惩罚
penalty_weights = {
    1: 0.15,  # 量化模型未通过：惩罚15%
    2: 0.10,  # 技术面未通过：惩罚10%
    3: 0.08,  # 情绪面未通过：惩罚8%
    4: 0.07   # 基本面未通过：惩罚7%
}

# 累计惩罚最高40%
total_penalty = min(0.40, sum(penalties))
adjusted_score = original_score * (1 - total_penalty)
```

#### **示例场景**

**股票A**: 原始得分75分
- 量化模型: ✓ 通过
- 技术面: ✗ RSI=78（超买）→ 惩罚10%
- 情绪面: ✓ 通过
- 基本面: ✗ PE=65（偏高）→ 惩罚7%

**结果**:
- 总惩罚: 10% + 7% = 17%
- 调整后分数: 75 × (1 - 0.17) = **62.25分**
- **✓ 通过筛选**（≥50分）

**解读**: 虽然技术面和基本面不理想，但量化信号强+情绪好，综合实力足够，给予通过机会。

- **熊市** (bear_market): 上证指数 < MA60 且跌幅 > 5%
- **震荡市** (oscillation): 其他情况（默认）
- **高波动** (high_volatility): 波动率 > 2%
- **低波动** (low_volatility): 波动率 < 1%

**分析维度**
```python

    'risk_level': 'medium',             # 风险水平 (low/medium/high)
    'confidence': 0.85,                 # 判断置信度 (0-1)
```

- 难以筛选出优质投资机会

### 优化方案

#### 1. 调整评级阈值 ✅

| 评级 | 旧阈值 | 新阈值 | 变化 |
|------|--------|--------|------|
| S级 | 85分 | 80分 | -5分 |
| A+级 | 75分 | 70分 | -5分 |
| A级 | 65分 | 60分 | -5分 |
| B级 | 50分 | 45分 | -5分 |

**优势**: 评级标准更合理，优质股票更容易获得较高评级

#### 2. 优化量化模型评分算法 ✅
**文件**: `analysis/opportunity_scorer.py:250-308`

**旧算法**:
```python
score = buy_ratio * 100 - sell_count * 2
```
- 问题：完全依赖买入比例，基础分为0

**新算法**:
```python
score = 40.0 + (buy_count * 2.5) + (hold_count * 0.5) - (sell_count * 1.5)
```

**特点**:
- 基础分40分（避免全0）
- 买入信号：每个+2.5分（最多30个模型=75分）
- 持有信号：每个+0.5分（微弱加分）
- 卖出信号：每个-1.5分（轻微惩罚）

**效果对比**:
| 场景 | 买入 | 持有 | 卖出 | 旧分数 | 新分数 | 提升 |

## 根本原因

### 1. 浏览器重复创建问题

**位置**: `analysis/dynamic_crawler.py`

**问题代码**:
```python
def crawl_guba_posts(stock_code: str, limit: int = 50):
    with sync_playwright() as p:
        browser = p.chromium.launch(...)  # 每次调用都创建新浏览器
```

**问题**：
- 每个股票分析都调用`InvestorSentimentAnalyzer`
- `InvestorSentimentAnalyzer`调用`DynamicCrawler.crawl_guba_posts()`
- `crawl_guba_posts()`每次都创建新的Playwright浏览器
- **10个并发线程 = 同时启动10+个浏览器实例**

### 2. 并发参数设置过高

**默认参数**:
- `max_workers=10` - 10个并发线程
- `batch_size=20` - 每批20只股票
- `stock_timeout=10` - 10秒超时

**问题**：
- 浏览器启动时间通常需要5-8秒
- 爬取页面需要3-5秒
- 总耗时约10-15秒
- **10秒超时对Playwright来说太短**

### 3. 资源耗尽

**并发场景**：
```
10个线程同时运行
  ↓
每个线程创建1个浏览器
  ↓
每个浏览器打开3-5个页面（候选URLs）
  ↓
同时存在30-50个浏览器页面
  ↓
内存耗尽 → 系统卡死
```

## 解决方案

### 1. 创建浏览器池管理器

**文件**: `utils/browser_pool.py` (新增)

**核心设计**：
```python
class BrowserPool:
    """浏览器池管理器 - 单例模式"""

    def __init__(self):
        self.playwright = None
        self.browser = None
        self.context = None
        self.usage_count = 0
        self.max_usage = 50  # 50次使用后重启

    @contextmanager
    def get_page(self):
        """获取页面上下文管理器"""
        # 自动管理页面生命周期
        page = self.context.new_page()
        try:
            yield page
        finally:
            page.close()
```

**优势**：
- ✅ 单例模式，全局唯一浏览器实例
- ✅ 线程安全（使用threading.Lock）
- ✅ 自动重启机制（防止内存泄漏）
- ✅ 上下文管理器（自动关闭页面）

```python
def _should_restart(self):
    """判断是否需要重启浏览器"""
    # 使用次数超限
    if self.usage_count >= self.max_usage:
        return True

    # 长时间未使用（5分钟）
    if time.time() - self.last_used > self.timeout:
        return True

    # 浏览器连接断开
    if self.browser and not self.browser.is_connected():
        return True
```

4. **更灵活**: 只有量化和技术两个维度进行硬筛选,其他维度仅影响排序

### 注意事项
1. 筛选通过率会提高,需要更依赖评分排序来选择标的
2. 建议设置最低综合得分阈值(如60分)来控制标的质量
3. 龙虎榜数据可能不稳定,需要做好异常处理
