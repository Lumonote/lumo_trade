## 🎯 参数调整依据

### 新的参数标准（来自用户提供的说明）

#### 1. Temperature (温度参数)
- **作用**: 控制预测的随机性
- **范围说明**:
  - 保守预测: 0.5-0.7（适合趋势明确的市场）
  - 平衡预测: 0.8-1.0（适用于一般市场环境）⭐
  - 激进预测: >1.0（适合高波动市场）
- **新默认值**: 0.8（平衡预测范围的起始值）

#### 2. Top-p (核采样概率)
- **作用**: 只考虑累积概率达到 top_p 的 token
- **推荐范围**: 0.8-0.95
- **作用**: 平衡多样性和稳定性
- **默认值**: 0.90（保持不变）

#### 3. Sample Count (采样次数)
- **作用**: 通过多次采样取平均值提高预测稳定性
- **建议范围**: 1-5次 ⚠️
- **新默认值**: 3次（之前是10次）
- **原因**:
  - 边际收益递减，超过5次提升有限
  - 提高计算效率，3次是最佳平衡点

#### 4. Lookback Window (历史数据窗口)
- **5分钟线**: 240-512个数据点
- **日线**: 252天（一年交易日）
- **作用**: 控制模型可见的历史数据长度

#### 5. Pred_len (预测步数)
- **短线交易**: 5-15分钟
- **长线投资**: 30-60天
- **作用**: 根据需求设置预测未来时间长度

## 📊 详细调整说明

### 1. Temperature: 0.6 → 0.8 🌡️

**调整原因**:
- 0.6 处于保守预测范围（0.5-0.7），过于保守
- 0.8 处于平衡预测范围（0.8-1.0）起始值，更适合一般市场

**影响**:
- ✅ **预测多样性提升**: 从过于保守转向平衡
- ✅ **适应性更强**: 适合更多市场环境
- ✅ **探索性增强**: 在保持稳定性的同时，探索更多可能性

**新的温度分类**:
```
保守预测: 0.5-0.7  → 趋势明确的市场
平衡预测: 0.8-1.0  → 一般市场环境（新默认值在此范围）
激进预测: >1.0     → 高波动市场
```

---

### 2. Sample Count: 10 → 3 🔢

**调整原因**:
1. **边际收益递减**
   - 测试表明，1-5次采样已经能平滑大部分随机性
   - 超过5次后，预测质量提升非常有限

2. **计算效率**
   - 3次采样比10次快 **3.3倍**
   - 显著降低计算资源消耗

3. **实践验证**
   - 大多数场景下，3次采样已经足够
   - 重要决策时可提高到4-5次

**影响**:
- ✅ **速度提升**: 预测速度提高3倍以上
- ✅ **资源节省**: CPU/GPU 使用率显著降低
- ✅ **质量保证**: 3次采样仍能保持良好的预测质量
- ✅ **灵活调整**: 用户可根据需求调整到1-5次

**新的采样次数建议**:
```
快速测试: 1-2次   → 资源受限，快速验证
日常使用: 3次     → 推荐默认配置（新默认值）
重要决策: 4-5次   → 追求更高稳定性
```

---

### 3. Top-p: 保持 0.90 ✅

**为什么不变**:
- 0.90 已经在推荐范围（0.8-0.95）内
- 处于平衡多样性和稳定性的最佳点
- 适配多种市场环境

**Top-p 使用建议**:
```
窄范围(0.80-0.85): 趋势明确，追求稳定
适中范围(0.90):    平衡多样性和稳定性（默认）
宽范围(0.95):      不确定市场，探索更多可能
```

## 核心参数详解

### 1. Temperature (温度参数) 🌡️

**作用**: 控制预测的**随机性**，值越小预测越确定，值越大预测越多样化。

| 温度区间 | 策略类型 | 适用场景 | 特点 |
|---------|---------|---------|------|
| **0.5-0.7** | 保守预测 | 趋势明确的市场 | 预测确定性高，紧跟主趋势 |
| **0.8-1.0** | 平衡预测 ⭐ | 一般市场环境 | 确定性和多样性平衡 |
| **>1.0** | 激进预测 | 高波动市场 | 探索多种可能性，预测分散 |

**核心原理**:
- **低温度 (0.5-0.7)**：模型倾向于选择概率最高的预测
  - ✅ 优势：稳定、保守、适合跟随明确趋势
  - ⚠️ 劣势：可能错过潜在机会

- **中温度 (0.8-1.0)**：平衡确定性和探索性
  - ✅ 优势：适应多种市场环境
  - ✅ 推荐作为默认配置

- **高温度 (>1.0)**：模型会探索更多可能性
  - ✅ 优势：适合高波动、不确定性高的市场
  - ⚠️ 劣势：预测波动大，需要更严格的止损

**调参建议**:

```bash
# 趋势明确市场（如强势上涨）- 保守策略
python examples/prediction_batch_example.py -s 000001 -T 0.6 -p 0.85 -n 2

# 一般市场环境 - 平衡策略（默认）
python examples/prediction_batch_example.py -s 000001 -T 0.8 -p 0.90 -n 3

# 高波动市场 - 激进策略
python examples/prediction_batch_example.py -s 000001 -T 1.2 -p 0.95 -n 5
```

---

### 2. Top-p (核采样概率) 🎯

**作用**: 只考虑累积概率达到 top_p 的 token，控制采样范围。

| Top-p值 | 采样范围 | 适用场景 |
|--------|---------|---------|
| **0.80-0.85** | 窄 | 趋势明确，追求稳定 |
| **0.90** | 适中 ⭐ | 平衡多样性和稳定性 |
| **0.95** | 宽 | 不确定市场，探索更多可能 |

**推荐范围**: 0.8-0.95

**核心原理**:
- **低 Top-p (0.8)**：只从累积概率前 80% 的候选中采样
  - 预测更集中、稳定
  - 适合趋势明确的市场

- **高 Top-p (0.95)**：从累积概率前 95% 的候选中采样
  - 预测更分散、探索性强
  - 适合震荡或不确定市场

**配合使用建议**:
- 保守组合：Temperature=0.6 + Top-p=0.85
- 平衡组合：Temperature=0.8 + Top-p=0.90
- 激进组合：Temperature=1.2 + Top-p=0.95

---

### 3. Sample Count (采样次数) 🔢

**作用**: 通过多次采样取平均值，提高预测稳定性。

| 采样次数 | 预测质量 | 计算成本 | 适用场景 |
|---------|---------|---------|---------|
| **1-2** | 基础 | 低 | 快速验证，资源受限 |
| **3** | 良好 ⭐ | 中 | 推荐默认配置 |
| **4-5** | 优秀 | 高 | 重要决策，追求稳定性 |

**建议范围**: 1-5次

**核心原理**:
- 多次采样可以平滑随机性，使预测更稳定
- **边际收益递减**：超过5次后，质量提升有限

**调参建议**:
- 快速测试：1-2次
- 日常使用：3次（默认）
- 重要决策：4-5次

# 评分与筛选系统优化

> 评分筛选系统是投资机会挖掘的核心,这些文档记录了评分算法和筛选逻辑的优化

# 投资机会评分系统优化总结 v2.3

## 优化背景

用户反馈投资机会挖掘系统整体分数偏低，评级标准过于严格，导致大多数股票评级为C级，不利于发现投资机会。

## 问题诊断

### 优化前存在的问题

1. **评级阈值过高**
   - S级: 85分 (几乎不可能达到)
   - A+级: 75分 (非常困难)
   - A级: 65分 (较难达到)
   - B级: 50分
   - C级: 50分以下

2. **量化模型评分过低**
   - 测试案例: 000001 (平安银行)
   - 30个量化模型中只有2个买入信号 (6.7%)
   - 26个持有信号 (86.7%)
   - 2个卖出信号 (6.7%)
   - **旧算法**: 买入比例 × 100 - 卖出数 × 2 = 6.7 - 4 = 2.7分
   - **问题**: 持有信号完全不加分，导致量化维度得分极低

3. **总分过低示例**
   - 000001: 总分38.2分 → C级
   - 量化: 6.0分 (贡献1.68分)
   - 技术: 55.0分 (贡献12.10分)
   - 其他维度正常

## 优化方案

### 1. 降低评级阈值 (更符合实际)

```python
# 优化前
RATING_THRESHOLDS = {
    'S': 85,   # S级：85分以上
    'A+': 75,  # A+级：75-85分
    'A': 65,   # A级：65-75分
    'B': 50,   # B级：50-65分
    'C': 0     # C级：50分以下
}

# 优化后
RATING_THRESHOLDS = {
    'S': 80,   # S级：80分以上  ↓ 降低5分
    'A+': 70,  # A+级：70-80分  ↓ 降低5分
    'A': 60,   # A级：60-70分   ↓ 降低5分
    'B': 45,   # B级：45-60分   ↓ 降低5分
    'C': 0     # C级：45分以下
}
```

**优化理由**:
- 原标准设定过于严格，导致评级分布极度不均
- 降低5分使评级更符合正态分布
- 更容易发现B级及以上的投资机会

### 2. 优化量化模型评分算法

#### 旧算法 (v2.2及之前)

```python
# 基础分数 = 买入比例 × 100
score = (buy_count / total_count) * 100

# 卖出惩罚: 每个卖出 -2分
score -= sell_count * 2

# 问题: 持有信号 = 0分贡献
```

**问题分析**:
- 在震荡市或调整期，大部分模型给出"持有"信号
- 持有信号完全不加分 → 量化得分接近0
- 即使没有卖出信号，买入比例低时得分仍然极低

#### 新算法 (v2.3优化)

```python
# 基准分: 40分 (代表市场中性状态)
score = 40.0

# 买入信号加分: 每个 +3分
score += buy_count * 3

# 卖出信号扣分: 每个 -1分 (降低惩罚)
score -= sell_count * 1

# 持有信号: 不加分不扣分，维持基准分
```

**优化要点**:
1. **基准分40分**: 持有信号不再是0分，而是有基础分
2. **买入加分更合理**: 每个买入信号+3分 (10个买入 = 70分)
3. **降低卖出惩罚**: 从-2分降为-1分，减少过度惩罚
4. **分数范围合理**: 0-100分，基准分40分

#### 评分示例对比

**案例: 000001 (2买入, 2卖出, 26持有)**

| 算法 | 计算过程 | 得分 |
|-----|---------|-----|
| 旧算法 | 2/30 × 100 - 2 × 2 = 6.7 - 4 | **2.7分** |
| 新算法 | 40 + 2 × 3 - 2 × 1 = 40 + 6 - 2 | **44分** |
| **提升** | - | **+41.3分** |

**实际测试结果**:
- 000001: 量化得分 6.0 → 38.0 (+32分)
- 600519: 量化得分 类似提升
- 688981: 量化得分 类似提升

## 主要变更

### 1. 新增技术指标

#### KDJ指标
- **KDJ_K**: KDJ指标的K值
- **KDJ_D**: KDJ指标的D值
- **KDJ_J**: KDJ指标的J值

KDJ用途:
- 识别超买超卖区域(J>90超买,J<20超卖)
- 金叉死叉信号(K线上穿D线为金叉买入信号)
- 配合RSI进行多指标确认

#### 均线指标扩展
- **MA60**: 60日均线(季线)
  - 用于判断长期趋势
  - 与MA5/MA10/MA20配合形成完整均线体系

#### 成交量指标
- **volume_ratio**: 量比(当日成交量/5日平均成交量)
  - >1.5为放量
  - 1.2-1.5为温和放量
  - 0.8-1.2为正常
  - <0.8为缩量

#### 均线趋势评分
- **MA_trend_score**: 0-5分评级系统
  - 5分: 完美多头排列(MA5>MA10>MA20>MA60且间距递增)
  - 4分: 长期趋势(MA5>MA10>MA20>MA60但间距较小)
  - 3分: 中期趋势(MA5>MA10>MA20但MA20<MA60)
  - 2分: 短期转强(MA5>MA10但MA10<MA20)
  - 1分: 弱势整理(均线纠缠)
  - 0分: 空头排列(MA5<MA10<MA20<MA60)

# Kronos 打包运行错误修复总结

## 问题描述

打包后的 Kronos Windows 程序运行批量预测功能时报错:

1. **PowerShell 脚本解析错误**
   ```
   Version : The term 'Version' is not recognized...
   ﻿# : The term '﻿#' is not recognized...
   ```

2. **PyTorch DLL 加载失败**
   ```
   OSError: [WinError 1114] 动态链接库(DLL)初始化例程失败。
   Error loading "C:\Users\palmer\AppData\Local\Kronos\venv\Lib\site-packages\torch\lib\c10.dll"
   ```

3. **模块导入失败**
   ```python
   from model import Kronos, KronosTokenizer, KronosPredictor
   # ModuleNotFoundError: No module named 'model'
   ```

## 根本原因分析

### 1. PowerShell 脚本 BOM 问题
- `quick_start.ps1` 文件使用 UTF-8 with BOM 编码
- BOM 标记 (`U+FEFF`) 导致 PowerShell 解析第一行时出错
- 解决方案: 移除 BOM,保持 UTF-8 编码

### 2. PyTorch 未打包问题
- **设计意图**: PyInstaller spec 文件中明确排除了 `torch` 库
- **原因**: PyTorch 体积巨大 (500MB-1.5GB),打包会导致程序体积过大
- **架构设计**: 程序使用外部虚拟环境中的 Python 和 PyTorch

### 3. 模块路径问题
- **问题**: 虚拟环境的 Python 无法找到打包后的 `model` 模块
- **原因**: PyInstaller 将代码打包到临时目录 `_MEIxxxxxx`,但虚拟环境的 Python `sys.path` 不包含该路径
- **本质**: 跨 Python 环境模块导入问题

## 修复方案

### 修复 1: 移除 PowerShell 脚本 BOM

```bash
# 使用 Python 移除 BOM
python3 -c "
with open('quick_start.ps1', 'r', encoding='utf-8-sig') as f:
    content = f.read()
with open('quick_start.ps1', 'w', encoding='utf-8', newline='\r\n') as f:
    f.write(content)
"
```

**修复结果**:
- 移除前: `Unicode text, UTF-8 (with BOM) text`
- 移除后: `Unicode text, UTF-8 text, with CRLF line terminators`

### 修复 2: 环境变量传递打包路径

修改 `quick_start.ps1` 中的 `Invoke-Python` 函数:

```powershell
function Invoke-Python {
    param(
        [Parameter(Mandatory=$true)][string]$Script,
        [Parameter(Mandatory=$false)][string[]]$Args
    )
    $python = Get-PythonCommand
    Write-Host "INFO: 使用 Python: $python" -ForegroundColor Cyan

    # 如果在打包环境中，设置环境变量以便Python脚本能找到模块
    $originalEnv = $env:KRONOS_PACKED_ROOT
    if ($IsPackaged) {
        $env:KRONOS_PACKED_ROOT = $scriptDir
        Write-Host "INFO: 设置打包路径: $scriptDir" -ForegroundColor Cyan
    }

    try {
        if ($Args) {
            & $python $Script @Args
        } else {
            & $python $Script
        }
    } finally {
        # 恢复原始环境变量
        if ($null -eq $originalEnv) {
            Remove-Item env:KRONOS_PACKED_ROOT -ErrorAction SilentlyContinue
        } else {
            $env:KRONOS_PACKED_ROOT = $originalEnv
        }
    }
}
```

### 修复 3: Python 脚本自动检测打包路径

修改 `examples/prediction_batch_example.py` 的导入逻辑:

```python
import tempfile

# 添加项目根目录到路径
# 支持打包后环境和开发环境
if getattr(sys, 'frozen', False):
    # 打包后环境 - 检查是否从打包的EXE调用
    if hasattr(sys, '_MEIPASS'):
        # PyInstaller临时目录
        project_root = Path(sys._MEIPASS)
    else:
        # 回退：使用当前文件的父目录
        project_root = Path(__file__).parent.parent
else:
    # 开发环境
    project_root = Path(__file__).parent.parent

sys.path.insert(0, str(project_root))

# 如果从外部Python调用（虚拟环境），尝试检测并添加打包路径
if 'model' not in sys.modules:
    # 尝试从环境变量获取打包路径
    packed_root = os.environ.get('KRONOS_PACKED_ROOT')
    if packed_root and Path(packed_root).exists():
        sys.path.insert(0, str(packed_root))
        print(f"INFO: 检测到打包环境路径: {packed_root}")
    else:

        temp_dir = Path(tempfile.gettempdir())
        mei_dirs = list(temp_dir.glob('_MEI*'))
        if mei_dirs:
            # 使用最新的_MEI目录
            latest_mei = max(mei_dirs, key=lambda p: p.stat().st_mtime)
            if (latest_mei / 'model').exists():
                sys.path.insert(0, str(latest_mei))
                print(f"INFO: 自动检测到打包环境路径: {latest_mei}")
```

# Windows打包PowerShell编码问题修复方案

## 问题描述

Windows打包后出现PowerShell脚本编码问题，主要表现为：

1. 中文字符显示为乱码
2. PowerShell解析器报语法错误
3. 脚本无法正常执行

## 问题原因

1. **编码问题**：PyInstaller打包时没有正确处理UTF-8编码的PowerShell文件
2. **BOM缺失**：Windows PowerShell需要UTF-8 BOM来正确识别编码
3. **字符串拼接**：PowerShell脚本中使用了不安全的字符串拼接方式

## 修复方案

### 1. PowerShell脚本修复

#### 1.1 编码设置

```powershell
# 强制UTF-8编码
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::InputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8

# 设置控制台代码页
chcp 65001 | Out-Null

# 设置PowerShell编码
$PSDefaultParameterValues['*:Encoding'] = 'utf8'
```

#### 1.2 字符串处理

将字符串拼接从：

```powershell
Write-Host ("STEP 步骤 " + $step + "/" + $totalSteps + ": 安装依赖...")
```

改为：

```powershell
Write-Host "STEP 步骤 $step/$totalSteps : 安装依赖..."
```

#### 2.1 PyInstaller Hook

创建 `packaging/hooks/hook-powershell.py`：

```python
# 确保PowerShell文件以UTF-8 BOM格式打包
```

在 `packaging/specs/kronos_windows.spec` 中：


### 3. 执行脚本优化

#### 3.1 批处理执行脚本

创建 `run_powershell.bat`：


## 🌟 二、技术核心：金融时序基础模型TSFM

### 2.1 从语言模型到时序模型

近年来，以ChatGPT为代表的大规模语言模型（LLM）在自然语言处理领域取得了革命性突破。这一成功启发了研究者：**能否将类似的技术应用于时间序列预测？**

**时序基础模型（TSFM）**应运而生。其核心理念是：
- ✨ 在海量时序数据上进行**预训练**
- 🎯 构建一个**通用的、与任务无关**的模型
- 🚀 支持**零样本学习**，无需额外训练即可应用到新任务

这种能力在金融领域尤为重要。想象一下：
- 当一只新股上市，历史数据稀缺时
- 当市场环境突然变化，传统模型失效时
- TSFM能够凭借其在大量数据上学到的"市场规律"，快速适应新情况

### 2.2 Kronos：专为金融K线打造

- 📉 **低信噪比**：市场充满随机波动和噪声
- 🌊 **强非平稳性**：趋势、周期性随时可能改变
- 🔄 **复杂依赖**：价格、成交量、市场情绪相互影响

通用的TSFM在面对金融数据时，往往"水土不服"。

## 🏗️ 三、Kronos架构解析

### 3.1 两阶段框架

Kronos的创新在于将连续的K线数据转化为"语言"：

```
阶段一：K线分词（K-line Tokenization）
┌──────────────────────────────────────┐
│  连续数据 → 离散令牌                  │
│  (OHLCV数据) → (层级化Token序列)      │
│  技术：Binary Spherical Quantization │
└──────────────────────────────────────┘
                    ↓
阶段二：自回归预训练（Autoregressive Pre-training）
┌──────────────────────────────────────┐
│  学习"语法" → 预测未来                │
│  GPT-2架构 → 由粗到精预测Token        │
│  能力：捕捉市场长期和短期规律         │
└──────────────────────────────────────┘
```

#### 为什么要"分词"？

传统方法直接预测价格，面临两大难题：
1. **数值空间连续**：价格可以是任何数值，预测难度大
2. **缺乏语义信息**：模型难以理解价格变化背后的"含义"

Kronos的分词策略，就像把股价走势翻译成"市场语言"：
- 📗 **绿色令牌**：小幅下跌
- 📕 **红色令牌**：大幅上涨
- 📘 **蓝色令牌**：震荡整理

模型学习这些"词汇"之间的规律，就能预测未来的"语句"。

## 🔍 五、进阶功能：投资机会挖掘系统

### 5.1 设计思路：从100到10的精选之路

**痛点**：
- 😵 A股4000+只股票，如何筛选？
- ⏰ 每日涨跌千只，如何抓住机会？
- 🎯 综合多维度信息，如何决策？

**解决方案**：
我们设计了一个**5阶段漏斗筛选系统**，就像"淘金"一样，层层筛选，最终留下真正的"金子"。

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        投资机会挖掘漏斗
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📥 初始池：100只热门股票
        ↓
┌──────────────────────────────┐
│ 🎯 阶段1：量化模型筛选         │
│ 条件：买入信号≥2个 或 比例≥20% │
│ 目标：过滤掉量化面偏弱的股票    │
└─────────────┬────────────────┘
              ↓ 通过 60-70只
┌──────────────────────────────┐

│ 条件：RSI<75 且 (MACD金叉    │
│       或 布林带突破)          │

└─────────────┬────────────────┘
              ↓ 通过 40-50只
┌──────────────────────────────┐
│ 😊 阶段3：市场情绪筛选         │

│       板块情绪≥45分           │

              ↓ 通过 25-35只

```

### 5.2 三种筛选模式

为适应不同的投资风格，系统提供三种筛选模式：

#### 🛡️ 保守模式（Conservative）

**适合人群**：稳健型投资者、风险厌恶者

**筛选标准**：
```
阶段1：买入信号≥5个 且 买入比例≥30%
阶段2：RSI<65 且 MACD金叉 且 布林带中轨上方
阶段3：股民情绪≥60 且 板块情绪≥55
阶段4：PE<40 且 营收利润双增长
阶段5：必须有利好消息
```

**特点**：
- ✅ 入选股票质量极高
- ✅ 多维度信号强烈一致
- ✅ 风险相对较低
- ⚠️ 筛选出的股票数量较少（5-10只）
- ⚠️ 可能错过部分潜力股

**适用场景**：
- 熊市或震荡市
- 账户资金量大
- 追求稳健收益

#### ⚖️ 平衡模式（Balanced）- 默认推荐

**适合人群**：大多数投资者

**筛选标准**：
```
阶段1：买入信号≥2个 或 买入比例≥20%
阶段2：RSI<75 且 (MACD金叉 或 布林带突破)
阶段3：股民情绪≥50 且 板块情绪≥45
阶段4：PE<60 且 营收或利润有增长
阶段5：利好≥利空（允许持平）
```

**特点**：
- ✅ 质量与数量兼顾
- ✅ 适应多数市场环境
- ✅ 操作空间较大
- ✅ 筛选结果10-15只
- 📊 质量与覆盖面平衡

**适用场景**：
- 所有市场环境
- 建立股票池
- 分散投资

#### 🚀 激进模式（Aggressive）

**适合人群**：激进型投资者、短线交易者

**筛选标准**：
```
阶段1：买入信号≥1个 或 买入比例≥10%
阶段2：RSI<85 (允许部分超买)
阶段3：股民情绪≥40 或 板块情绪≥35
阶段4：PE<80 (允许高估值成长股)
阶段5：不考虑事件面
```

**特点**：
- ✅ 捕捉更多潜在机会
- ✅ 包含高风险高收益标的
- ✅ 筛选结果15-25只
- ⚠️ 单个标的风险较高
- ⚠️ 需要更强的风控能力

**适用场景**：
- 牛市或强势市场
- 追求高收益
- 短线操作

### 5.3 智能多维度打分系统

每只股票通过6个维度进行评分（0-100分）：

#### 📊 评分维度权重

**基础权重模板**：
```
量化模型（Quantitative）：32% 🎯
  - 30个量化模型的买入信号数量
  - 买入信号比例
  - 模型一致性

技术分析（Technical）：24% 📈
  - RSI、MACD、布林带
  - 均线排列
  - 趋势强度

股民情绪（Sentiment）：10% 😊
  - 股吧讨论情绪
  - 舆情热度

板块情绪（Sector）：14% 📊
  - 板块涨跌幅
  - 板块活跃度
  - 龙头效应

基本面（Fundamental）：10% 💼
  - 估值水平
  - 成长性
  - 盈利质量

事件消息（Events）：10% 📰
  - 利好消息数量
  - 利空消息数量
  - 重大事件
```

#### 🎛️ 动态权重调整

系统会根据市场环境和股票特征**动态调整权重**：

**趋势牛市权重**（强趋势、低风险）：
```
量化模型：42%（↑10%）🔥
技术分析：24%（持平）
股民情绪：8%（↓2%）
板块情绪：12%（↓2%）
基本面：8%（↓2%）
事件消息：6%（↓4%）

触发条件：
  ✓ 买入信号比例≥60%
  ✓ 卖出信号≤2个
  ✓ 事件风险非高
  ✓ 板块涨幅≥0 或 板块得分≥60
```

**高风险/消息面主导权重**：
```
量化模型：22%（↓10%）
技术分析：22%（↓2%）
股民情绪：15%（↑5%）⬆️
板块情绪：21%（↑7%）⬆️
基本面：10%（持平）
事件消息：10%（持平）

触发条件：
  ✓ 事件风险包含"高"
  或 事件得分≤40
```

## 🎓 七、系统优势与创新点

### 7.1 技术创新

#### 🧠 深度学习+量化的完美结合

```
传统量化：
  ✓ 规则明确，可解释性强
  ✗ 固定规则，适应性差
  ✗ 难以捕捉复杂模式

深度学习：
  ✓ 强大的模式识别能力
  ✓ 自适应学习
  ✗ "黑盒"，可解释性差

Kronos融合方案：
  ✅ Kronos模型提供预测趋势
  ✅ 30种量化模型提供可解释信号
  ✅ 双重验证，互相印证
  ✅ 既有AI的智能，又有规则的可靠
```

#### 🎯 多维度综合决策

大多数系统只关注单一维度：
- 纯技术分析系统：只看K线和指标
- 纯基本面系统：只看财务数据
- 纯情绪分析系统：只看舆情

**Kronos的优势**：
```
6个维度同时评估
  ↓
加权综合打分
  ↓
动态权重调整
  ↓
最终评级
```

就像看病，不能只看体温，要**综合望闻问切**。

#### 🔄 智能自适应

**市场环境感知**：
```python
if 牛市趋势:
    提高量化模型权重（更看重趋势）
    降低事件面权重（消息面噪音多）
elif 高风险环境:
    提高情绪面权重（市场情绪主导）
    降低量化模型权重（量化失效）
else:
    使用平衡权重
```

**智能容差**：
- 当筛选过严时自动放宽
- 当筛选过松时自动收紧
- 确保始终有合理数量的推荐

```
性能提升：3-5倍 ⚡
```

### 8.3 参数调整

#### 预测参数（用于单股分析）

```bash
python examples/prediction_batch_example.py \
    --stock-code 600519 \
    --temperature 0.8 \        # 采样温度（0.5-1.5）
    --top-p 0.90 \            # 核采样阈值（0.8-0.95）
    --sample-count 3           # 采样次数（1-5）
```

**参数说明**：
- **Temperature（温度）**
  - 保守：0.5-0.7（适合趋势明确的市场）
  - 平衡：0.8-1.0（适合一般市场）
  - 激进：>1.0（适合高波动市场）

- **Top-p（核采样）**
  - 推荐范围：0.8-0.95
  - 平衡预测的多样性和稳定性

- **Sample Count（采样次数）**
  - 1次：最快，但可能不稳定
  - 3次：平衡速度和稳定性（推荐）
  - 5次：最稳定，但耗时较长

#### 筛选参数（用于机会挖掘）

```bash
    --workers 15 \               # 并发线程数

    --timeout 12 \               # 单股超时(秒)
    --filter-mode aggressive \   # 筛选模式
    --no-smart-tolerance         # 禁用智能容差
```
